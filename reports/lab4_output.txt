
======================================================================
FS data format
======================================================================
Disk layout (block = 64 bytes, a block number is a 2-byte integer):

    block 0             superblock: magic "FS4", block count, descriptor count
    bitmap blocks       1 bit per block, 1 = block is used
    descriptor blocks   file descriptors, 16 bytes each, 4 per block
    data blocks         file contents, directory contents, indirect blocks

File descriptor (16 bytes):
    type (1) | links (1) | size (2) | direct[4] (4 x 2) | indirect (2) | unused (2)

    direct[k] is the block with file bytes [k*64, (k+1)*64).
    indirect is a block holding 32 more block numbers (file blocks 4..35).
    Block number 0 means "no block": the offset is past the end of the file
    or the block contains only zero bytes. Block 0 is the superblock, so it
    can never be a data block.

Directory entry (16 bytes):
    used (1) | descriptor number (2) | name (13, padded with zero bytes)

    used = 0 marks a removed hard link; its slot is reused by the next link.
    The directory is descriptor 0 and stores its entries like file data,
    so it can hold at most 2304 / 16 = 144 entries.

======================================================================
1. Formatting
======================================================================

// The disk image is new, nothing works before mkfs.
> ls -l
error: file system is not formatted, call mkfs first
> mkfs 16
formatted: 1024 blocks of 64 bytes, 16 file descriptors, 1017 free blocks

// The directory is a file too (descriptor 0); '.' means the directory.
> stat .
  File: .
  Size: 0         Blocks: 0       IO Block: 64    directory
 Inode: 0         Links: 1
   Map: direct []   indirect -

======================================================================
2. The example from the task (block size here is 64, not 128)
======================================================================

// Create a regular file, output information about it.
> create file.txt
descriptor = 1
> stat file.txt
  File: file.txt
  Size: 0         Blocks: 0       IO Block: 64    regular file
 Inode: 1         Links: 1
   Map: direct []   indirect -

// Output the contents of the directory.
> ls -l
total 0 blocks
inode  type  links   size  blocks  name
    1     -      1      0       0  file.txt

// Create another name for the file: the number of hard links becomes 2.
> link file.txt document.txt
> ls -l
total 0 blocks
inode  type  links   size  blocks  name
    1     -      2      0       0  file.txt
    1     -      2      0       0  document.txt
> stat document.txt
  File: document.txt
  Size: 0         Blocks: 0       IO Block: 64    regular file
 Inode: 1         Links: 2
   Map: direct []   indirect -

// Create a file and make it 1024 bytes long: no blocks are used.
> create some.dat
descriptor = 2
> ls -l
total 0 blocks
inode  type  links   size  blocks  name
    1     -      2      0       0  file.txt
    1     -      2      0       0  document.txt
    2     -      1      0       0  some.dat
> truncate some.dat 1024
> stat some.dat
  File: some.dat
  Size: 1024      Blocks: 0       IO Block: 64    regular file
 Inode: 2         Links: 1
   Map: direct []   indirect -

// Open the file, write 10 bytes: 1 block is used.
> open some.dat
fd = 0
> write 0 10
0123456789
> stat some.dat
  File: some.dat
  Size: 1024      Blocks: 1       IO Block: 64    regular file
 Inode: 2         Links: 1
   Map: direct [8]   indirect -

// The offset can be set for the file.
> seek 0 7
> read 0 2
78   [2 bytes read]

// Write into the third block (offset 2 * 64 = 128), read the first three blocks.
> seek 0 128
> write 0 7
abcdefg
> seek 0 0
> read 0 192
0123456789\0\0...(118 zero bytes)...\0\0abcdefg\0\0...(57 zero bytes)...\0\0   [192 bytes read]
> stat some.dat
  File: some.dat
  Size: 1024      Blocks: 2       IO Block: 64    regular file
 Inode: 2         Links: 1
   Map: direct [8, -, 9]   indirect -

// Remove the only hard link: the open file still works.
(free blocks: 1014)
> unlink some.dat
> ls -l
total 0 blocks
inode  type  links   size  blocks  name
    1     -      2      0       0  file.txt
    1     -      2      0       0  document.txt
> seek 0 0
> read 0 10
0123456789   [10 bytes read]

// Closing the last fd frees the file (2 blocks).
> close 0
(free blocks: 1016)

======================================================================
3. Numerical file descriptors and offsets
======================================================================

// open gives the smallest free number; one file can be opened several times.
> open file.txt
fd = 0
> open file.txt
fd = 1
> open document.txt
fd = 2
> close 1
> open file.txt
fd = 1
> close 9
error: bad numerical file descriptor: 9

// Every fd has its own offset.
> write 0 11
hello world
> read 1 5
hello   [5 bytes read]
> read 1 100
 world   [6 bytes read]
> read 1 10
   [0 bytes read]
> seek 0 6
> write 0 5
WORLD
> seek 2 0
> read 2 100
hello WORLD   [11 bytes read]
> seek 0 -1
error: negative offset
> read 0 -1
error: negative size
> close 0
> close 1
> close 2

======================================================================
4. Big file: direct blocks and the indirect block
======================================================================

// 400 bytes = 7 blocks: 4 direct + 3 whose numbers are in the indirect block.
> create big
descriptor = 2
> open big
fd = 0
> write 0 400
ABCDEFGHIJKLMNOPQRSTUVWXYZABCDEFGHIJKLMNOPQRSTUVWXYZABCDEFGH ... GHIJKLMNOPQRSTUVWXYZABCDEFGHIJ   (400 bytes)
> stat big
  File: big
  Size: 400       Blocks: 7       IO Block: 64    regular file
 Inode: 2         Links: 1
   Map: direct [9, 10, 11, 12]   indirect 13 -> [14, 15, 16]

// A read across the direct/indirect border (offset 256).
> seek 0 250
> read 0 12
QRSTUVWXYZAB   [12 bytes read]
> seek 0 0
> read 0 400
ABCDEFGHIJKLMNOPQRSTUVWXYZABCDEFGHIJKLMNOPQRSTUVWXYZABCDEFGH ... GHIJKLMNOPQRSTUVWXYZABCDEFGHIJ   (400 bytes)   [400 bytes read]
(equal to what was written: True)

// The file cannot grow past 2304 bytes.
> seek 0 2304
> write 0 1
error: file size limit is 2304 bytes
> close 0

6. A file open twice after its last hard link is removed
======================================================================
> create tmp
descriptor = 5
> open tmp
fd = 0
> open tmp
fd = 1
> write 0 100
ABCDEFGHIJKLMNOPQRSTUVWXYZABCDEFGHIJKLMNOPQRSTUVWXYZABCDEFGHIJKLMNOPQRSTUVWXYZABCDEFGHIJKLMNOPQRSTUV
(free blocks: 1004)
> unlink tmp

// Closing the first fd frees nothing, the file is still open.
> close 0
(free blocks: 1004)
> seek 1 90
> read 1 20
MNOPQRSTUV   [10 bytes read]

// Closing the second fd frees the 2 data blocks.
> close 1
(free blocks: 1006)

======================================================================
7. Blocks of zeros are not stored
======================================================================
> create sparse
descriptor = 5
> open sparse
fd = 0

// Writing 128 zero bytes uses no blocks.
> write 0 128
\0\0...(128 zero bytes)...\0\0
> stat sparse
  File: sparse
  Size: 128       Blocks: 0       IO Block: 64    regular file
 Inode: 5         Links: 1
   Map: direct []   indirect -

// Writing in the middle uses only the block that was written (file block 10).
> seek 0 640
> write 0 3
END
> stat sparse
  File: sparse
  Size: 643       Blocks: 1       IO Block: 64    regular file
 Inode: 5         Links: 1
   Map: direct []   indirect 18 -> [-, -, -, -, -, -, 19]

// When the block becomes all zeros again, it is freed (and the indirect block too).
> seek 0 640
> write 0 3
\0\0\0
> stat sparse
  File: sparse
  Size: 643       Blocks: 0       IO Block: 64    regular file
 Inode: 5         Links: 1
   Map: direct []   indirect -
> close 0

======================================================================
8. truncate down
======================================================================

// Shrinking frees the blocks after the new end and the unused indirect block.
> open big
fd = 0
> seek 0 400
(free blocks: 1006)
> truncate big 70
> stat big
  File: big
  Size: 70        Blocks: 2       IO Block: 64    regular file
 Inode: 2         Links: 1
   Map: direct [9, 10]   indirect -
(free blocks: 1012)

// The fd offset (400) is now past the end: read returns nothing.
> read 0 10
   [0 bytes read]

// Growing again: the bytes after the old end (70) read as zeros, not old data.
> truncate big 200
> seek 0 64
> read 0 12
MNOPQR\0\0\0\0\0\0   [12 bytes read]
> close 0
> truncate big 5000
error: size must be 0..2304

12. mkfs again, then fill the whole disk
======================================================================

// mkfs on a formatted disk starts a new empty file system.
> mkfs 40
formatted: 1024 blocks of 64 bytes, 40 file descriptors, 1011 free blocks
> ls -l
total 0 blocks

// Create files of 2304 bytes until the disk is full.
(27 full files written, then the disk ran out)
> stat full27
  File: full27
  Size: 256       Blocks: 4       IO Block: 64    regular file
 Inode: 28        Links: 1
   Map: direct [1020, 1021, 1022, 1023]   indirect -
(free blocks: 0)

// Remove all files: every data block comes back, nothing is lost.
(removed full0 .. full27)
(free blocks: 1003)
(free blocks right after mkfs: 1011; the difference is the directory itself:)
> stat .
  File: .
  Size: 448       Blocks: 7       IO Block: 64    directory
 Inode: 0         Links: 1
   Map: direct [13, 162, 311, 460]   indirect 609 -> [610, 759, 908]
